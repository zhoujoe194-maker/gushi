# GushiOS V2 项目上下文

广州固实内部经营协作平台，面向中国建材及制造业员工。优先减少录入、及时跟进、避免项目遗漏，再连接采购、交付与资金风险；中文、手机可用、服务端权限和财务准确性优先。

## 权限与业务
三个工作台：销售、管理、财务；不存在运营/售后台，也没有内部岗位范围切换。`members.desks` 的 sales/management/operations/aftersales/finance 只作历史授权/岗位能力持久化兼容，读取时映射到三工作台；旧 `default_desk` 原样保留并读作所属工作台（运营/售后→管理）。运营、售后、技术、物流等只是管理工作台内的真实专业岗位。
工作台授权不等于管理权限。公司管理权限只来自真实专业岗位（owner/management/general/director/branch_manager），必须显式授予并审计前后角色与授权；勾选管理工作台或保留旧 operations/aftersales 授权不会获得 manager 角色、公司项目、人员管理、工资成本或现金权限。仅 owner 可授予/取消管理岗位。
owner 在管理工作台默认财务只读；合同审核、实际收付、银行核销、工资费用等财务写操作必须进入已授权的财务工作台。销售仅访问正式归属 memberId 的项目和必要商务字段；转交后只保留本人任期结果快照，不能读取当前项目、合同、群聊或附件。历史任务和台间/私聊消息按原持久授权保留，不合并成全员管理群；历史私人消息不因管理身份开放。
项目只需名称即可创建，销售自动绑定本人；跟进只需文字、日期选填，独立追加，普通编辑不算跟进。暂停/丢单必须原因并留历史，暂停进入管理复查。任务、消息、报价、合同、销售考核等现有能力保留。

## 架构与数据
Next.js App Router、React、TypeScript；自托管 Node 24+、SQLite，保留 Cloudflare/D1 适配。db/schema.ts 与 drizzle SQL 迁移；服务端 API 经身份、工作台范围、项目与字段权限检查。projects 关联成员、跟进、结果事件、任务、群聊与 finance_books；公司费用、核销与凭证沿用现有财务模型，详见 ARCHITECTURE.md。
金额为整数分；合同金额、确认计划、实际到账分开。草稿不算正式应收，部分支付只预测余额，结清不因编辑重开。采购批次、报销、工资和固定支出联动13周情景预测，不连接真实银行转账。
