# 第三阶段 C：项目收支与现金流

## 复用方案

客户收款计划和实际到账沿用 `finance_books.plans/receipts`；采购付款沿用 `finance_books.suppliers/payments`；订单、报销作为同一项目台账的扩展。交付批次沿用项目 `execution.batches`。合同总额和订单总额是核对上限/业务信息，不独立计入现金流。

银行流水仅记录一次银行业务与分摊关系，实际金额仍由原项目记录及公司费用支付明细汇总，不能再叠加银行流水金额。新增的公司费用只覆盖原项目账本不含的工资、租金等业务。所有计划和核销具有稳定 ID，变更保留审计；金额输入转为整数分，汇总检查安全整数上限。

`0013_cashflow.sql` 为增量迁移，不删除或重写原表。每次跨项目核销在一个事务里验证全部相关版本，写银行流水和各项目余额；任何失败整体回滚。重复请求 ID、银行流水号、同笔重复分摊及超额核销均受校验。

## 分批记录

### C1

项目收支标签、回款信息、采购订单与交付批次、货期建议、报销及凭证、统一银行核销和冲销。原合同页面的实际收付款接入同一核销服务。销售仅看到客户侧回款、必要货期及本人报销；单独的报销授权不开放完整项目。

43 项真实 HTTP / 临时数据库测试通过，覆盖部分报销、跨项目分摊、重复流水、月结建议、货期改变、财务权限和故障回滚。生产构建、TypeScript 检查通过。后续批次将追加结果。

### C2

工资、社保、公积金、租金、税费、贷款本金利息及其他费用/收入复用统一核销流程。周期计划按指定金额、日期和 1–24 次生成有限记录，相同月份同项费用防重复。参考上月工资生成草稿，确认后进入预测；工资所属月不代替付款日期。工资包含社保公积金时，拒绝再次确认同月对应费用。

工资预算与实付分别保存。财务明确勾选结清时，实际金额可高于或低于预算，剩余预算不再进入预测。未勾选且未付清时保留剩余待付。65 项累计接口检查通过，包含跨月、重复周期、二月日期收敛、工资差异与权限。生产构建和 TypeScript 通过。
