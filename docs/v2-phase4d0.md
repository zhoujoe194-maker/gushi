## 修复结果与文件

1. `app/server/cash-company.ts`：普通编辑不能将 settled 改为 confirmed/draft/cancelled，也不能凭普通保存制造 settled。结清记录允许修改名称、备注、确定性说明，保护原预算、月份、类别、日期和费用包含关系。超预算实付也允许编辑备注，原预算不被抬高覆盖。审计历史和支付明细继续保留。
2. `app/company-expenses.tsx`：编辑结清记录默认保持 settled，并明确显示“已结清（普通编辑保持结清）”，取消原来的隐式 confirmed 转换。伪造 API 状态变化仍由服务端拒绝。
3. `app/finance-model.ts`：totals 以明确 cashStatus 为优先；旧无状态计划沿用合同审核状态。scheduled 为确认计划合计，balance/overdue 为对应计划逐笔扣除有效实际收款后的余额，草稿排除。received 是所有有效实际到账，不等同合同金额。销售投影保留 cashStatus 和 certainty，避免前端将草稿误读为正式应收。
4. `app/server/cash-store.ts`：销售项目收支投影保留合同 reviewStatus，确保旧无 cashStatus 的历史计划与旧合同界面口径一致。
5. `app/server/cash.ts`：已审核合同的确认计划合计必须等于合同金额；同时拒绝超额增加和单独调低导致差额。合同审核仍沿用既有计划编号并验证金额与已收款，未重写历史金额。
6. `tests/v2-cashflow.mjs`：新增 10 项接口回归，覆盖万元预算差额结清、备注编辑、伪造状态、超预算、银行冲销恢复待付、合同差额与销售旧合同状态。
7. `tests/cash-forecast-unit.mjs`：新增 6 项计算回归，覆盖草稿排除、销售投影、新旧页面应收一致、确认后增加、部分收款与冲销。
8. `tests/v2-cashflow-browser.mjs`：新增 1 项浏览器回归，实付小于预算并结清后，用界面修改备注，再核对 settled 和零待付。

## 计算与状态边界

- 已结清公司费用未来待付始终为零，预算与实际差异不自动重开。普通编辑只能保留结清，不提供新的主动重开功能。
- 银行整笔冲销属于明确的独立财务操作，必须填写原因，保留原流水及审计，并恢复计划 confirmed 和对应未付余额。跨项目核销继续整体事务处理，不做部分冲销。
- 未结清的部分支付只预测剩余金额；明确结清后的超预算或少付预算，只进入历史实际现金流。
- 正式应收基于已确认计划，草稿不计入。实际到账独立统计，合同总额是业务约定金额，不能当作实际到账。
- 旧合同列表可按“已审核合同”筛选；对相同项目和确认计划，新旧页面使用相同的余额含义。独立确认计划即便没有已审核合同，也在项目收支和公司现金流中生效。
