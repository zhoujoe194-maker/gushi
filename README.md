# 固实能源 · 公司业务协同工作台

面向公司内部使用的独立部署版本。包含售后、销售、管理、财务、运营五个工作台；支持邮箱或手机号加密码登录、岗位权限、独立任务下发、结果验收、项目跟进、合同与票款协作。

完整部署、账号初始化、备份和升级步骤见 [部署说明](部署说明.md)。

上线业务核验、日常备份与以后更新流程见 [上线验收与更新](deploy/上线验收与更新.md)。构建后运行 `RUN_LOCAL_TESTS=1 npm run test:release` 可在隔离数据库中验收主要业务；健康接口为 `/api/health`，本机探针为 `npm run healthcheck`。

## 本机运行

需要 Node.js 24 和 npm。

```sh
npm ci
npm run db:migrate
```

创建 `.env.local`，填写 `APP_ORIGIN=http://127.0.0.1:5173`、`INITIAL_ADMIN_EMAIL=admin@example.com` 和 `INITIAL_SETUP_TOKEN`。启用码请使用密码管理器生成的 24–128 位随机值（字母、数字、下划线或短横线），不要使用个人密码。然后运行：

```sh
npm run dev -- --hostname 127.0.0.1 --port 5173
```

首位管理员邮箱已在 `deploy/env.production.example` 中预填为 `admin@example.com`。全新数据库首次打开网站会进入 `/setup`：填写启用码、真实姓名及个人密码，即可启用并进入五台选择页面，无需执行 `admin:create`。启用后入口自动关闭；已有任何账号时不会开放重新认领。`admin:create` 保留用于服务器侧账号恢复或兼容旧部署方式。部署包不包含管理员密码或预建账号。演示页面 `/demo?role=sales` 使用虚构数据，操作不会写入公司正式数据库。

## 正式部署

推荐使用本目录的 Dockerfile、compose.yaml 和 deploy/nginx.conf.example。先准备域名、服务器、HTTPS 和备案，再按部署说明开通访问。独立版不依赖 ChatGPT 登录，也不会自动迁移原 ChatGPT Sites 上的数据。

此配置使用单实例 SQLite 持久化数据库。密码以加盐摘要保存，账号由管理员开通；员工首次登录或重置后必须修改密码。


## 站内消息中心

五个工作台均有“消息中心”菜单和顶部未读入口。支持个人对个人、台对台、个人对台（含工作台回复个人）。发起会话时选择本人或所属台的发送身份，以及个人或工作台接收方。

- 私聊仅双方本人可见，管理和管理员不会自动获得旁观权限。
- 工作台会话由该台当前成员共享，跨分部；发送时保留实际成员姓名。每位成员独立记录未读，调岗后失去原台共享会话访问权。
- 关联项目遵守现有项目权限；无权限的接收人不会看到项目名称和编号。
- 正式消息保存在服务器数据库；演示消息保存在当前浏览器，可切换演示岗位体验，二者完全隔离。
- 活跃聊天约 5 秒刷新，未读约 8 秒刷新；支持历史记录分页。Enter 发送、Shift + Enter 换行。
- 沟通不自动创建或验收任务；需要期限和验收的事项可由销售或管理下发任务。本期为文字消息与项目关联，不含附件和外部推送。

本地升级先备份，再运行 `npm run db:migrate`；新增迁移为 `0004_internal_messages.sql` 和 `0005_message_indexes.sql`。

消息权限集成测试只可使用隔离的本机数据库。设置 `RUN_LOCAL_TESTS=1`、`DATABASE_PATH=/private/tmp/gushi-message-qa/company.sqlite` 和 `QA_URL=http://127.0.0.1:5181`，并让测试服务使用同一数据库及 APP_ORIGIN，再运行 `node tests/messages-integration.mjs`。不要指向员工使用的数据库。


## 首次启用、真实姓名和多个工作台

1. 部署负责人配置预设管理员邮箱和随机启用码。新网站首页自动进入首次启用向导，由持有启用码的人填写真实姓名并设置个人密码；没有启用码不能创建管理员。
2. 管理员完成网页启用后直接进入管理台的“人员管理”，添加员工账号。填写邮箱或手机号、初始密码、所属分部，并勾选一个或多个可进入的工作台和默认台。
3. 员工统一在首页使用邮箱或手机号和密码登录，首次确认真实姓名并修改初始密码；未完成之前，业务接口和工作台均不开放。
4. 单台员工直接进入对应工作台，多台员工进入 `/workspaces` 选择，并可在顶部切换。姓名是本人填写确认，不是身份证实名认证；系统不接入第三方核验。

账号开通由管理员在管理台完成，没有公开自助注册。测试完整开通流程时，先用管理员账号登录并完成首次设置，再到“人员管理”添加一个测试成员、分配工作台和初始密码；用另一个浏览器窗口以该成员身份登录，完成姓名确认和改密。测试结束后在人员管理中停用该成员。

工作台由账号授权决定。服务端验证 `X-Workspace-Desk`，不会因为修改 URL 或请求头而得到未授权岗位。不同浏览器页签可停留在不同的已授权工作台，账号仍为同一人。项目、任务、消息和财务操作使用当前台的权限。

公司管理台可开通成员、修改多台授权、设置默认台、重置密码及停用账号；分部管理只可维护本分部普通成员，不能分配管理权限。系统管理员账号不在人员管理中变更，自己的权限需由其他管理人员调整。权限变化或停用会撤销被修改成员的所有登录；已确认姓名在重置密码时保留。

升级前备份，再运行 `npm run db:migrate`。迁移 `0006_member_access.sql` 为旧成员保留原岗位并要求下次登录确认姓名；旧的命名和业务历史不删除。初始管理员拥有五台权限，默认管理台。

本地验收：`tests/access-integration.mjs` 在 `/private/tmp/gushi-access-qa/company.sqlite` 验证首次启用、姓名确认、管理开通、多台数据隔离、权限回收及密码重置；仅可用于隔离测试环境。

## 项目群聊

销售或管理在有权查看的项目详情中点击“创建项目群”，也可从“消息中心 → 创建项目群”选择项目。填写群名称、勾选同事即可建群；“选入项目对接人”可选入项目主跟、部门对接人和协作承办人，再按实际需要调整。每群支持 2–100 位公司成员，创建者自动成为群主。

- 群聊按个人成员名单授权，不随当前工作台切换而丢失。只有入群成员可见；管理员和管理台不会自动旁观未加入的群。
- 群主在销售台或管理台、群内管理人员在管理台且仍有项目查看权限时，可修改群名、添加或移出成员。群主和当前操作人保留在群内；普通成员只能查看名单和发言。
- 新成员可查看全部群聊历史；移出后服务端立即拒绝继续读取或发送，已打开的页面在下一次同步时收起会话。停用账号不能访问群聊。
- 群名称、消息正文和群成员名单对群内成员共享。加入群不会自动授予项目主档、合同或财务资料的查看权限；无权查看项目的人看到的项目关联已隐藏编号与名称。
- 群聊以本人身份发言，沿用历史分页、独立未读、消息重试去重；建群、改名和成员变更会留下群内系统记录。普通私聊和工作台会话继续可用。
- 群聊用于沟通，需要负责人、期限和验收的事项可使用销售或管理的“下发任务”。

已有部署升级前先备份，再执行 `npm run db:migrate`，新增迁移为 `0007_project_groups.sql`；Docker 启动脚本也会自动应用迁移。演示群聊只保存在当前浏览器，不会写入真实业务数据库。

群聊权限验收：`tests/groups-integration.mjs` 使用隔离数据库 `/private/tmp/gushi-message-qa/groups-qa.sqlite`，配合 `RUN_LOCAL_TESTS=1`、`DATABASE_PATH` 和 `QA_URL` 执行。禁止指向员工使用的数据库。

## 独立任务下发

- 销售和管理台首页、项目页都提供“下发任务”，与“新建项目”并列；任务页也可下发。
- 填写任务名称、承办工作台、完成期限、要求与验收标准。可指定有对应工作台权限的成员，也可交给目标台认领。
- “关联项目”选填；不选择即可创建独立任务，不会创建空项目。期限由下发人填写，不自动推算。
- 销售在“任务下发与跟进”查看“我下发的”或“本台收到的”；只能调整或取消自己下发的任务，不能跨分部下发。
- 承办人保存进展、提交结果；管理台负责验收通过或退回。待验收或已关闭任务不能直接修改要求。取消须填原因，历史记录保留。
- 待办、即将到期、逾期和待验收状态显示在相关工作台；当前为页面自动刷新提醒，不含短信、邮件或外部推送。

## 销售工作记录、周报与月度绩效

销售台和管理台均新增“销售考核”，按 2026 年 8 月发布的制度设置。销售使用本人账号填写，管理按授权分部审核；兼任管理的销售不能审核自己的记录或发布自己的月度结果。

- **工作记录**：填写日期、工作类型、处理结果和可核实依据，可关联项目；新增线索需填写客户、负责人联系方式和项目进度。支持拓客、拜访、老客回访、方案、厂家沟通、培训、回款等 12 类工作。管理核实通过后计入指标，退回须说明原因；补充、审核均留存历史。
- **销售周报**：填写本周进展、下周计划、风险协调和依据。每周六 24:00（北京时间）截止，跨月周按周六所属月份归档。每人每周一份，系统保存首次提交和最近提交时间，迟交状态不会因修改而抹掉。页面统计已到截止日的应交、已交、迟交、未交数量。
- **月度绩效**：13 项指标按行为 25 分、能力 50 分、业务 25 分，总分 100。销售逐项自评并提交，管理结合已核实记录逐项评分，说明依据；本月结束且待核实材料处理完成后才能发布结果。70–79.9 分必须填写改进计划。
- **月结保护**：发布后锁定该月记录；需更正时，由管理填写原因退回月度考核，再补充材料、重新自评及发布。历次核定结果、依据快照、审核人和时间保留；过期版本或并发修改会要求刷新。
- **查阅与导出**：“制度与成长”列明评分细则、来源、岗位职责、培养和晋升参考；按成员和月份可导出 CSV。普通销售只能查看本人，公司管理查看公司，分部管理限本分部。

采用详细《销售考核关键点》及月度表的周六截止口径；岗位说明书“周五前汇总”作为工作安排参考。2026 年 8 月为过渡期，扣分只记录提醒。激励表的 500／250／100／0 元与薪资表绩效栏 0 存在差异，网站仅显示激励参考，具体执行由公司确认。客户消息时效、微信群协同、培训安排、费用等由管理凭证核实，评分不自动从外部聊天推断，也不自动发薪或变更人员岗位。

本功能按确认范围只记录销售履职、周报与绩效，不包含上下班打卡、定位或请假考勤。依据字段保存文字说明与凭据位置，不上传原始政策文件、不连接微信读取聊天、不发送外部邮件或短信。

升级新增 `0008_sales_performance.sql`，先备份后迁移；Docker 启动时自动应用。专项测试 `tests/sales-integration.mjs` 只允许 `/private/tmp/gushi-sales-qa/` 下的隔离数据库和本机测试服务。

## 任务图片与销售考核演示

任务“处理结果与进展”下方可添加 JPG、PNG、WebP 静态图片，当前结果最多 6 张，每张最多 5 MB。先填写文字结果、选图并检查预览，再点“保存进展”或“提交验收”。保存后可查看大图；退回补充时可调整图片。已提交图片从当前结果移除后仍保留在任务历史中，不能抹掉原提交依据。

正式图片由服务器校验实际格式、完整解码，自动旋正并缩至最长 2400 像素、转换为 WebP，去除 EXIF 等元信息；不支持动态图片、HEIC、SVG 或超过 2500 万像素的图片。图片与任务、审核历史在同一数据库事务中保存，在线备份包含图片。读取沿用任务的下发人、承办台和管理范围；没有公开静态图片地址，停用或无权账号不能读取。

演示区的销售考核已有虚构成员、工作记录、周报、自评与上级评分。本月展示待审核和退回材料，历史月份展示已发布及待核定示例；可试填、审核、评分发布、退回与导出，并可“重置演示”。所有演示修改仅保存在页面内存，刷新、切换工作区或重置后恢复，不写入真实员工数据。演示任务也支持本地选图预览，图片不上传服务器。

新增迁移 `0009_task_images.sql`。测试：`tests/task-images-integration.mjs` 在 `/private/tmp/gushi-access-qa/` 隔离数据库验证上传、图片权限、格式大小、并发和事务回滚。

## 业务员周报与月报（2026-10-31）

销售考核新增“销售月报”。周报和月报均按实际报表填写：周报提交数量、厂家对接、项目统筹报备、有效线索、新老客户、培训、交办事项、有效拜访及报价／技术方案。新老客户各按同行、设计、业主、采购分类，另列其中电联家数和客户清单；填写本期总结、下一期计划、风险及核实依据。

数量空白为未填，零为没有发生；分类完整时必须与总数一致，电联不能超过总数。月报按自然月去重，不自动累加周报客户数。人工填报的周报应交／实交数与平台周六截止记录分别保留，供管理核对。实际报表未给出统一月报截止日，不自动判定月报迟交。

工作记录新增客户属性、客户类别、沟通方式和重点行业。已核实的电话／线上记录不计入现场拜访数量；明确为现场拜访的老客户回访可计入，历史未注明方式的客户拜访保留原口径。周报和月报的填报数量不自动替代既定 13 项评分。管理评分时可展开当月月报作为依据；本月待审核月报会阻止发布考核，发布后锁定关联材料。旧文字周报继续可读。

“导出本月”CSV 包含新增数量、分类、电联、说明、总结和计划，可用 Excel 打开。演示区同步提供虚构周报、月报和可操作审核流程；实际案例中的姓名及客户信息未导入演示或成员库。
