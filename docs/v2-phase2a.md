# GushiOS V2.0 · 第二阶段 A 验收说明

本阶段只实现极简创建、快速跟进、相关权限及既有销售合同/报价适配。在 codex/gushios-v2 分支开发；未合并 main、未部署。未开展阶段 B、三工作台整体改版或新的任务完成流程。

## 新旧操作流程

| 操作 | 以前 | 阶段 A |
|---|---|---|
| 新建项目 | 多项资料及下一步行动、日期；负责人选择器 | 销售只填项目名称，服务端绑定本人 memberId |
| 补充资料 | 与必填项混排 | 可展开“补充资料”，保留客户、地址、产品、报备等原功能 |
| 记录跟进 | 提交整个项目并填写阶段、下一步和日期 | 文字必填，日期选填，独立追加记录 |
| 留空下次日期 | 活跃项目验证阻止保存 | 保存成功，当前标记“待安排跟进”，旧记录的日期保留 |
| 最近跟进 | 通用项目更新时间可能被当作跟进 | 专用 lastFollowupAt，只由跟进写入 |
| 手机项目列表 | 横向表格 | 小屏按项目卡片排列，提供“记录跟进”按钮 |
| 合同/报价 | 第一阶段收紧权限后入口需适配 | 本人项目合同提交、开票申请及销售报价恢复；不返回成本利润等数据 |

项目详情默认打开动态，显示最近真实跟进、最新内容和下次日期。原详细工程阶段继续保留为补充信息，阶段 A 不改变业务状态体系。

## 修改文件

- app/workspace.tsx：极简表单、快速跟进弹窗、详情摘要、列表入口、合同入口。
- app/globals.css：手机表单、列表卡片和触摸按钮样式。
- app/role-dashboard.tsx：原首页卡片优先显示最新跟进内容，未重做首页结构。
- app/model.ts：可选跟进元数据、空默认日期、提醒按真实跟进判断。
- app/server/validation.ts：取消强制下一步计划；兼容取消分部后的旧字段值。
- app/api/workspace/route.ts：最小创建默认值、负责人验证、跟进独立分发、字段级返回。
- app/server/followups.ts：内容和日期独立校验，服务器时间，原子写入项目摘要、跟进表和事件表；请求幂等及版本冲突控制。
- app/server/projects.ts：普通编辑保留服务器控制的真实跟进元数据。
- app/team.ts：仅在本人项目授权必要合同字段，不扩大 canViewFinance。
- app/finance-model.ts、app/api/finance/route.ts：销售财务白名单投影及合同流程适配。
- app/server/commercial-access.ts、app/project-business.tsx：销售可维护售价和报价，不能修改成本利润；隐藏值保存时不被覆盖。
- tests/v2-foundation.mjs：更新必要合同投影断言，继续禁止完整财务台账。
- tests/v2-lightweight.mjs：60 项真实 HTTP 接口与临时数据库测试。
- tests/v2-lightweight-browser.mjs：桌面、手机、平板交互验证及截图。

## 验证结果

- 生产构建通过，TypeScript 检查通过，git diff --check 通过。
- 60 项接口检查通过，包含第一阶段权限基础，以及名称创建、默认负责人、防伪造、多次跟进、空日期、空内容/非法日期、重试幂等、并发冲突、任务/负责人/资料变更与跟进隔离。
- 销售合同提交、财务审核、销售开票申请、报价修改通过；合同返回不包含成本快照、厂家付款或内部财务备注。
- 原项目可读取；原销售转交后不能通过旧请求重试读取项目。
- 11 项浏览器检查通过：1440px 桌面创建与跟进；390px 手机创建、跟进、合同提交、补充资料、列表一键跟进；360px 小屏与 768px 平板输入无横向溢出；无页面运行时异常。
- 浏览器自动化证明操作能完成，但“员工 30 秒完成”仍需用户实际试用计时，不以自动化速度替代员工验收。

验证输出位于工作区 outputs/gushios-v2-phase2a，包含 build.txt、typecheck.txt、integration.txt、browser.txt 和页面截图。数据库和试用密码不提交 Git。

## 数据兼容与边界

本阶段沿用第一阶段 0012 数据表，不再增加或重写历史迁移。新建/跟进仅新增可选 JSON 元数据；旧字段、旧项目 ID 和旧事件保留。旧记录没有结构化真实跟进时间时不把普通 updatedAt 冒充跟进；历史文字仍可在原动态中查看。

用户已确认现有业务数据均为模拟数据。本次从既有体验库复制出独立 trial.sqlite，新增四个试用账号、生成六条模拟跟进；浏览器验收又创建了模拟项目。没有清空原预览库、修改其账号密码或运行生产部署。
